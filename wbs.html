平衡说明：管理员端业务最复杂（10+ 页面含指派逻辑），所以工时略多；公众监督员端和大屏端业务相对单一，工时略少。差异控制在 5h 以内。
阶段边界（防重合）： 启动=空壳能跑（工程/登录/代理/公共模板）； 全量=业务页 + 真实接口（含统计后端）； 联调=对数据格式、空数据、边界用例，禁止再写一遍同名接口。 每人只 scaffold 自己负责的端；公共 request.js 模板由 C 提供，A/B/D 复制后改端口。

阶段二：D2-D4 四端并行开发

2.A NEPS 公众监督员端 全量
A 6 h D2

页面清单（5 个）

  • 注册页：手机号（Blur 查重）、真实姓名、出生日期、性别单选、密码、确认密码
  • 登录页：手机号+密码，登录后跳选择网格
  • 选择网格地址：省-市二级联动（Change 事件重查市），下一步按钮跳 AQI 选择
  • AQI 选择+反馈：展示 6 等级参考表 + 单选预估等级 + 多行文本反馈框 + 提交按钮
  • 历史反馈列表：按当前用户查自己提交过的所有反馈，下拉刷新

对应后端接口

  • POST /api/supervisor/register（含手机号唯一性校验）
  • POST /api/supervisor/login
  • GET /api/region/provinces GET /api/region/cities/{provinceId}
  • GET /api/aqi/levels POST /api/aqiFeedback/submit
  • GET /api/aqiFeedback/myList?supervisorId=...

关键交互

  • 手机号 Blur 调 GET /api/supervisor/checkPhone?phone=xxx，已注册就提示
  • 省下拉 Change 事件清空市下拉并重查
  • 提交反馈成功后跳历史列表

2.B NEPG 网格员端 全量
B 7 h D2

页面清单（3 个）

  • 登录页：登录编码+密码（无注册，HR 系统管理）
  • 指派任务列表：显示所有指派给当前网格员的任务，含网格地址、预估等级、状态
  • 确认 AQI 详情：展示任务详情 + 3 个浓度输入框（SO2/CO/PM2.5）+ 实时计算 + 提交

对应后端接口

  • POST /api/gridMember/login
  • GET /api/aqiFeedback/assignedList?gridMemberId=...
  • GET /api/aqiFeedback/detail/{id}
  • POST /api/aqiFeedback/confirm（提交实测数据，自动算总 AQI）

AQI 计算核心逻辑（重点）

  • 公式：AQI = MAX(IAQI_SO2, IAQI_CO, IAQI_PM2.5)
  • 每个浓度输入框 Change 事件：根据《浓度限值表》查出 IAQI 等级
  • 前端实时显示分项等级 + 综合等级（颜色按等级变色：优/良/轻/中/重/严重）
  • 提交时后端再算一次做校验，前端算的是体验、后端算的是权威

限值表数据准备

  • SO2 一级 0-150、二级 150-500、三级 500-650、四级 650-800…（μg/m³）
  • CO 一级 0-5、二级 5-10、三级 10-35、四级 35-60…（mg/m³）
  • PM2.5 一级 0-35、二级 35-75、三级 75-115、四级 115-150…（μg/m³）
验收：D2 晚上群里发截图：跑通登录→看任务→填浓度→实时看到 AQI 等级→提交成功

3.3 Bug 修复 + 验收演示

  • 空数据：管理员查某无数据的省 → 不能报错，前端显示"无数据"
